Unchanged from 1.0: everything on the attendance side — check-in and check-out, the repeating missed-punch alerts, regularization inside a configurable window, shifts by location, present-by-default, and the location-based holiday calendar. The HR document covers leave only, so sections 15 to 20 carry forward as they were.
Still ours, not HR's. Three mechanics are design decisions rather than stated requirements: shifts and leave policies are versioned by effective date, so editing one does not rewrite history; punches on a shift that crosses midnight stay attached to the shift's start date; and leave balance is a ledger of movements rather than a stored number, which is what lets HR correct a balance without destroying what was there before.
This is now built, not just designed. The schema, services, API and scheduled jobs described here exist in the backend and are applied to the development database. Where the build taught us something the design had wrong, this document was corrected to match the code rather than the other way round — three places, each flagged where it occurs:
  • the probation column is ConfirmationStatus, because EmploymentStatus was already taken (section 27);
  • only tblRegularizationType is editable master data — the attendance statuses and holiday types carry fixed ids the code branches on (section 27);
  • two defects in the leave ledger, found by running it against a real database, are corrected by migrations 021 and 022 (section 27).
The two open questions in section 28 — the EL accrual anchor and the comp-off validity period — are configuration columns in the shipped schema, so answering them is an update, not a change to the code.

Stage 1Probation

20

Holidays, by location

India and the US have different holidays and festivals. A holiday is linked to one or more locations, and an employee sees only the calendar for the location they are assigned to.

Type 1Normal holiday

Applies to everybody at the linked locations. Non-working, nothing to choose. Independence Day is one row linked to India; Thanksgiving is one linked to the US; New Year's Day is one row linked to both.

Type 2Floating / Restricted holiday

The curated list HR uploads for the calendar year. The employee picks one from it — the detail is in section 07, because the entitlement behaves as a leave category.

HR Admin can add, edit and delete holidays. Delete is a soft delete, so a holiday that days are already marked against never leaves the table.

A holiday links to locations through a link table rather than carrying a single LocationId. One column would force either a duplicate row per location or a nullable "all locations" special case, and the first bug either produces is a US employee seeing an Indian festival.

tblEmployeeDetails is the hub. Attendance hangs off one side, leave off the other, and location scopes the configuration both read. Four things changed here in 2.0 — they are marked v2.0.
